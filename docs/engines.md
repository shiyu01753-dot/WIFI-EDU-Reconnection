# 引擎扩展接口

三种引擎：加密网页认证、表单网页认证、系统网络恢复。内部标识分别是 `srun`、`form`、`system`。

配置窗口通过发现模块设置内部引擎，不向用户提供选择器。识别失败不默认套用网页引擎。发现模块只读取页面、同源脚本指纹与匿名状态，读取表单属性但不读取浏览器凭据；初次入口发现可以跟随无凭据的跨服务器页面跳转，认证阶段仍禁止跨服务器提交。

引擎接收 `config`、内存中的密码、状态写入函数和可选测试依赖，由 `runEngine` 分发。引擎只做单次检测与恢复，定时器与唤醒重试由托盘界面管理。

新增引擎时，应实现同样的异步接口并注册到 `ENGINES`，同时增加配置窗口字段、校验与真实或合成验证。不要把用户名、密码、网关或学校参数写入源码。

状态包括 `online`、`waiting`、`connecting`、`authenticating`、`blocked`。认证拒绝和无法确认的表单响应使用 `blocked`，停止重复认证；暂时断网使用 `waiting`。

网络配置字段：`portalUrl`（用户确认的服务器）、`acId`（可选数字）、`wifiProfile`（已保存网络名称）、`engine`。表单还使用 `formLoginPath`、`formUsernameField`、`formPasswordField` 和 `formSuccessMarker`。

认证请求不跟随跨服务器跳转；表单提交路径不能携带查询参数或指向其他主机。HTTPS 保留证书校验；日志不能写入网址、表单正文、凭据或原始服务器响应。

目前表单引擎是简单 POST，不自动处理 Cookie、CSRF、多步认证或验证码。系统网络引擎只恢复操作系统保存的 Wi-Fi，不完成网页认证。加密引擎是一个具体协议示例，不具备通用认证识别能力。
